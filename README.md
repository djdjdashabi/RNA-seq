# RNA editing workflow and Supplemental File 1

This repository contains the Section 7 analysis scripts at its repository root. The supplemental ZIP places the same scripts inside scripts/. The two layouts are deployed as described below. Analysis parameters, figures, and existing results have not been regenerated by this documentation revision.

## Project deployment

For a NEW project, run these commands from the desired parent directory. Do not clone over a non-empty scripts directory or replace an existing project.

```bash
mkdir -p Supplemental_files
git clone https://github.com/djdjdashabi/RNA-seq.git Supplemental_files/scripts
cd Supplemental_files
mkdir -p reference annotation bam results logs
```

Alternatively, extract scripts/ from Supplemental File 1 into Supplemental_files/ and skip git clone. The required resulting layout is:

```text
Supplemental_files/
  scripts/  (Snakefile, config.section7.yaml, Python scripts)
  reference/
  annotation/
  bam/
  results/
  logs/
  SPRINT/   (staged upstream source tree including sprint_from_bam.py)
  JACUSA2/  (staged JACUSA_v2.1.16.jar)
essay/resources/downloads/  (archived NCBI source files; sibling resource directory)
```

Run manuscript commands from Supplemental_files/. Parenthesized command blocks enter subdirectories temporarily and return automatically. Configuration paths are relative to scripts/. The archived NCBI source files are ../../essay/resources/downloads/Homo_sapiens.gene_info.gz and ../../essay/resources/downloads/gene2go.gz from scripts/. Preserve this sibling layout, or edit both configuration entries and pass matching source arguments to the optional manual Step 4.3 invocation. build_gene2go.py also searches annotation/ under the project root. Newly generated manifest paths are project-root-relative; existing provenance records remain historical records. Portable /usr/bin/env shebangs are retained.

## Environment preparation

The four definitions below were exported from the installed Linux environments on 2026-10-16. Conda versions and build strings are retained, and the machine-specific prefix is removed. They describe the current installation, not an independently established historical run environment. They have not been used to recreate fresh environments or rerun the manuscript analysis. Packages installed by pip have version pins but no artifact hashes, so these are environment specifications, not a complete byte-for-byte lock.

Use Conda on Linux x86-64 or Ubuntu WSL2. For each environment, copy its YAML block to the indicated temporary YAML filename, then run the corresponding conda env create command. Create only missing environments; do not replace existing analysis environments. Conda must be initialized in the shell for conda activate to work. Package availability and successful environment solving must be confirmed on the destination machine. Python 2.7 is a legacy runtime and must remain isolated.

These third-party sources and binaries are not included in the environment exports. Do not silently substitute a different release. Verify the file presence from the project root:

```bash

```

## Run and restart Section 7

Stage all six native caller outputs and the references described in the manuscript first. Step 4.3 may build the human Gene files once. Step 7.1 must not call that script directly again; let Snakemake determine which dependencies need rebuilding:

```bash
conda activate snakemake_env
(cd scripts && snakemake -j 8)
```

The same command checks the up-to-date targets on a subsequent unchanged run. Do not rerun all preprocessing or calling commands just to perform this check. protocol_commands.txt contains manuscript excerpts in reading order, not an unattended end-to-end executable script.

standardize_callers.py initializes strand_consistent to an empty value; annotate_candidates.py derives gene-strand compatibility. Figure 5 uses strand_mode=all. The consistent analysis is available in code but is not the displayed GO analysis. Script figure1 through figure4 correspond to manuscript Figures 2 through 5; figure_data.tsv uses script-level numbering. Figure 1 is supplied separately.
